# 第10章第2节：可靠性与成本

## 写在前面

能跑通 demo ≠ 能扛线上。  
可靠性让服务「少挂」；成本控制让账单「少炸」。两者往往共用同一批旋钮：超时、步数、模型路由。

## 生活例子

外卖平台：超时自动取消、高峰限流、热门菜缓存、简单单走近店。  
Agent 服务也一样。

## 本节你将学会

1. 可靠性最低清单如何映射到本仓库已有代码  
2. 成本最低清单里哪些旋钮已经存在  
3. 如何写一个极简的模型路由规则

## 一步一步讲 + 对照仓库

### 可靠性最低清单

| 项 | 含义 | 本仓库落点 / 缺口 |
|----|------|-------------------|
| 超时 | 模型/工具/全局不能无限等 | `OpenAICompatClient` 有 `timeout`；工具应各自超时 |
| 重试 | 只对瞬时错误、幂等操作 | 结构化输出有重试；HTTP 工具可按状态码重试 |
| 限流 | 防止被打爆 | API 层尚未做——生产加网关/中间件 |
| 降级 | 主模型失败换备用 | `build_default_client` 可扩展 fallback |
| 幂等键 | 同一请求别重复副作用 | `POST /runs` 可接收 `Idempotency-Key`（待加） |
| 步数刹车 | Agent 死循环 | `AgentLoop.max_steps`、`AgentRequest.max_steps` |

### 成本最低清单

| 项 | 做法 | 本仓库 |
|----|------|--------|
| 小模型分流 | 简单问题走小模型 | 见下方练习 `route_model` |
| 压缩历史 | 短期记忆截断/摘要 | 第4章 memory |
| 截断工具结果 | 观察别无限长 | `loop._truncate` |
| 限制 max_steps | 少一轮少花钱 | 已有 |
| 缓存 | 重复查询命中缓存 | 检索/HTTP 可加（未内置） |

### 和 API 的关系

`app.py` 当前同步 mock、无队列、无限流。上线前至少：

```text
请求进入
  → 鉴权 + 限流
  → 写入 pending run
  → worker 执行 AgentLoop（带 timeout/max_steps）
  → 写回 succeeded/failed
  → 日志带 run_id + usage
```

## 打开代码一起看

1. `AgentLoop.__init__(..., max_steps=8)`：成本与安全双保险  
2. `_truncate(..., limit=4000)`：防止工具把上下文撑爆  
3. `Settings` 里的 `openai_model`：换小模型只改配置  
4. `AgentRequest.max_steps`：调用方可按场景收紧
