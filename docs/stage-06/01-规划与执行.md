# 第6章第1节：先规划，再执行

## 写在前面

当任务变长，「边走边想」容易绕路。Plan-and-Execute = 先列出步骤，再逐步做。

## 生活例子

旅行：先写行程（Day1/Day2），再按天执行；航班取消就改计划。

## 一步一步讲

1. Planner 输出步骤列表（JSON）  
2. Executor 逐步执行（教学里用 LLM「假装执行」；生产里调工具/子 Agent）  
3. 失败可 Replan（本仓库最小版尚未自动重规划，留作练习）

适合：调研报告、多文件修改。不适合：超短问答。

## 打开代码一起看（逐行教材版）

打开 `src/agent_lab/planning/plan_execute.py` 与 `examples/stage06_plan_execute_demo.py`。

### 1）计划的数据形状（复用第2章结构化）

```python
class PlanStep(BaseModel):
    id: str
    title: str
    detail: str = ""

class Plan(BaseModel):
    goal: str
    steps: list[PlanStep] = Field(min_length=1, max_length=8)
```

### 2）`plan()`：强制 JSON 计划

```python
return await complete_structured(
    self.client,
    system="你是规划器。只输出 JSON：{...}",
    user=goal,
    model_type=Plan,
)
```

这里直接调用你在第2章写过的 `complete_structured`。

### 3）`execute_step()`：教学版执行器

```python
result = await self.client.chat([
    ChatMessage(role="system", content="你是执行器。用 1-2 句中文描述…"),
    ChatMessage(role="user", content=f"{step.title}\n{step.detail}"),
])
return StepResult(step_id=step.id, ok=bool(text.strip()), output=text)
```

注释写得很清楚：真实项目这里应调工具，而不是再让模型「演戏」。

### 4）`run()`：串起来

```python
plan = await self.plan(goal)
for step in plan.steps:
    results.append(await self.execute_step(step))
final = "；".join(r.output for r in results if r.ok)
```

注意：当前是**串行**；某步 `ok=False` 仍继续下一步——生产常加「失败则 break / replan」。

### 5）mock 演示为何能跑通

`stage06_plan_execute_demo.py` 用 `MockLLMClient(script=[计划JSON, 步骤1结果, 步骤2结果])`，按调用顺序吐出。

```powershell

```
