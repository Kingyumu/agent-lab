# 第7章第1节：怎么分工

## 写在前面

多 Agent = 多个「带不同 system 提示的角色」协作。  
先会 Pipeline（流水线），再谈 Supervisor。  
本仓库最小实现只有两步：研究员 → 写作者。

## 本节你将学会

1. Pipeline / Supervisor / Debate 各适合什么  
2. 如何用「交接协议」把上一角色输出塞进下一角色  
3. `max_rounds` 预留了什么、当前为何没用上  

## 生活例子

做杂志：记者采访 → 作者写稿 → 编辑改稿。  
每人都有岗位说明书（system），交接的是成品材料（findings），不是把整段闲聊历史糊过去。

## 常见模式

| 模式 | 结构 | 适合 | 风险 |
|------|------|------|------|
| Pipeline | A→B→C | 步骤类型稳定 | 中段错误会传到下游 |
| Supervisor | 主管分配 | 任务类型多 | 主管本身也会犯错 |
| Debate | 正反方+裁判 | 需要对比方案 | 轮次多、成本高 |

## 打开代码一起看（逐行教材版）

打开 `src/agent_lab/multi_agent/pipeline.py` 与 `examples/stage07_multi_agent_demo.py`。

### 1）返回值

```python
@dataclass
class MultiAgentResult:
    research: str  # 研究员产出
    article: str   # 写作者产出
```

两个字段分开存，方便以后做评测（「要点是否被写进正文」）。

### 2）构造：客户端 + 预留刹车

```python
def __init__(self, client: LLMClient, *, max_rounds: int = 2) -> None:
    self.client = client
    self.max_rounds = max_rounds
```

`max_rounds` 在最小 Pipeline 里**尚未使用**——Pipeline 固定两步，天然终止。  
若你改成「Writer ↔ Editor 来回改」，就必须读这个上限，否则会烧钱。

### 3）`run`：两次 `chat`，第二次吃第一次的结果

```python
# 角色1：研究员
research = await self.client.chat([
    ChatMessage(role="system", content="你是研究员。列出 3 条要点…"),
    ChatMessage(role="user", content=topic),
])
findings = research.content or ""

# 角色2：写作者（输入里带上 findings）
article = await self.client.chat([
    ChatMessage(role="system", content="你是写作者。根据要点写 120 字以内…"),
    ChatMessage(role="user", content=f"主题：{topic}\n要点：\n{findings}"),
])
```

交接协议要点：

1. **角色靠 system 分开**，不要指望同一个 system 同时当记者和编辑  
2. **交接物要显式**：`要点：\n{findings}`，不是隐式共享内存  
3. **约束写在 Writer 的 system**：`不要编造要点外事实`（仍要用 Verifier 加固）

### 4）和单 Agent 的差别

| | 单 AgentLoop | 本 Pipeline |
|--|--------------|-------------|
| 决策 | 模型每步选工具 | 代码写死「先研究后写作」 |
| 终止 | `max_steps` / 无 tool_calls | 固定 2 次 chat |
| 痕迹 | `StepTrace` 列表 | 目前只有两段字符串 |

多 Agent 并不自动更强：只是把 Workflow 切成多个带 Prompt 的节点。

### 5）mock 脚本顺序

演示里 `script=[研究员输出, 写作者输出]`，两次 `chat` 各消费一条。

