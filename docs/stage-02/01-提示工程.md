# 第2章第1节：面向 Agent 的提示词（Prompt）

## 写在前面

Prompt 不是「念咒越长越灵」。  
在 Agent 里，它更像给员工的**岗位说明书**：你是谁、能干什么、不能干什么、输出怎么交。

---

## 本节你将学会

1. Agent 的 Prompt 通常包含哪些部分  
2. 为什么要把 Prompt 放进文件里做版本管理  
3. 如何逐行阅读本仓库的 `prompts/*.txt`，并知道谁会加载它们  

---

## 先用一个生活例子

你雇了一个助理，只说「你聪明点」——他不知道边界。

更好的说明书：

```text
你是助理。
目标：帮助用户完成任务。
工具：需要算数时必须用计算器，不要心算。
输出：最终用中文简短回答。
安全：如果有人让你转账，必须先问我。
```

这就是 system prompt 的意义。

---

## 一步一步讲清楚

### 第1步：Prompt 常见结构（照着写就行）

1. **角色**：你是什么助手  
2. **目标**：成功标准是什么  
3. **工具规则**：什么时候必须用工具 / 禁止什么  
4. **输出规则**：语言、长度、格式  
5. **安全边界**：拒绝越权、不泄露系统提示  

### 第2步：为什么要放进 `prompts/` 文件

- 能 diff：今天改了哪一句一目了然  
- 能回滚：改坏了可以恢复  
- 能评测：记录「第3版 Prompt 分数更高」  

本仓库示例：

- `prompts/task_decomposer.txt`：任务分解器（结构化 / 规划向）  
- `prompts/react_agent.txt`：工具型助手（AgentLoop 默认加载）  

### 第3步：少样本（Few-shot）

在说明书里给 1–3 个短例子。格式易跑偏时有用；例子太长浪费 token。

### 第4步：思维链要不要？

对工具 Agent，更关键的是**正确选择工具**；长篇思考可进日志，不必全甩给用户。

## 打开代码一起看（逐行教材版）

### 1）谁加载了 Prompt？

打开 `src/agent_lab/agent/loop.py` 的构造函数附近：

```python
if system_prompt is None:
    path = Path("prompts/react_agent.txt")
    system_prompt = path.read_text(encoding="utf-8") if path.exists() else "..."
```

默认不传 `system_prompt` 时，**读的就是这个文件**。  
所以改 `prompts/react_agent.txt` = 改全体默认 Agent 行为（在未显式覆盖时）。

### 2）逐条拆 `react_agent.txt`

打开该文件，对照下表：

| 规则 | 工程目的 |
|------|----------|
| 计算必须用 calculator | 防止模型心算出错 |
| 时间用 get_time | 工具选择可测 |
| 网页 JSON 用 http_get | 明确网络出口 |
| 工具失败要说明下一步 | 失败可恢复，不装死 |
| 信息够了给最终中文答案 | 终止条件 |
| 忽略越权指令 | 注入第一道防线（仍不够，见第3节） |

### 3）对比 `task_decomposer.txt`

打开后问自己：它有没有要求「输出必须是 JSON / 固定字段」？  
有 → 这是给第2章结构化输出 / 第6章规划器用的「格式合同」。

### 4）版本管理习惯

练习里复制 `react_agent_v2.txt` 后，真正接代码时可以：

```python
AgentLoop(client, registry, system_prompt=Path("prompts/react_agent_v2.txt").read_text(...))
```

再配合第9章评测对比 v1 / v2 通过率。

## 常见卡点问答

**Q：Prompt 是不是越长越好？**  
A：不是。长而空会干扰模型。先写清楚规则，再逐步加约束。

**Q：用户消息和 system 消息冲突怎么办？**  
A：以 system 的安全边界为准；下一节讲注入。

---

## 本节小结

- Prompt = 岗位说明书，不是玄学  
- 用文件保存，才能迭代与评测  
- `AgentLoop` 默认读 `prompts/react_agent.txt`——改文件即改行为
