# 第2章第2节：结构化输出（让程序能读懂）

## 写在前面

模型喜欢写漂亮文章。  
程序需要的是**固定字段**的数据。

本节教你一套初学就够用的稳妥办法：

```text
要求模型输出 JSON
  → 用程序提取 JSON
  → 用 Pydantic 校验
  → 失败就把错误发回去让它改（有限次）
```

---

## 本节你将学会

1. 为什么 Agent 离不开结构化输出
2. 「提取 JSON + 校验 + 重试」三步如何配合
3. 跑通任务分解示例

---

## 先用一个生活例子

你让助理「列学习计划」。

他回：

```text
好的！我们可以先……然后……最后……（一大段散文）
```

你没法自动排进日历。

你若要求：

```text
只输出 JSON：
{"goal":"...","steps":[{"id":"s1","title":"..."}]}
```

程序就能继续处理。

---

## 一步一步讲清楚

### 第1步：约定 Schema（表格长什么样）

例如：

```json
{
  "goal": "学习 Python AI Agent",
  "steps": [
    {"id": "s1", "title": "打好工程基础", "detail": "..."},
    {"id": "s2", "title": "手写 Tool Loop", "detail": "..."}
  ]
}
```

对应 Pydantic 模型（示例里叫 `TaskPlan`）。

### 第2步：模型常犯的错

- 前后加上 \`\`\`json 代码围栏
- 少字段
- 字段类型错（该列表给了字符串）
- 输出解释性废话

所以不能「相信它一次成功」。

### 第3步：程序侧三层防线

1. Prompt 里写清 Schema（必要但不充分）  
2. 若平台支持 Structured Outputs / JSON mode，可开启（进阶）  
3. **Pydantic 校验 + 失败重试**（本教材必做）

### 第4步：重试时要说人话错误

不要只说「再试一次」。要说：

```text
缺少字段 steps；请只输出 JSON 对象，不要 Markdown。
```

模型更容易改对。

### A. `parse_json_object`：从乱七八糟的文本里抠 JSON

模型经常这样返回：

````text
```json
{"goal":"...","steps":[...]}
```
````

或前后带废话。函数大致做三件事：

1. 去掉 \`\`\`json 代码围栏  
2. 整段 `json.loads`；成功且是 `dict` 就返回  
3. 失败再用正则找第一段 `{...}`，再 `loads`

失败则抛 `StructuredOutputError`。

---

### B. `parse_as_model`：抠完再安检

```python
def parse_as_model(text: str, model_type: type[T]) -> T:
    data = parse_json_object(text)
    return model_type.model_validate(data)  # Pydantic：缺字段/类型错会报错
```

示例里的 `TaskPlan` 要求：`goal` + 至少 2 个 `steps`。  
JSON 语法对但字段不对，也会在这一步失败。

---

### C. `complete_structured`：调用 → 校验 → 失败重试

```text
准备 system + user
    ↓
循环最多 retries+1 次：
    若不是第一次：追加一条 user「上次错了，错误是…」
    await client.chat(messages)
    把 assistant 回复追加进 messages
    尝试 parse_as_model
        成功 → 返回 Pydantic 对象
        失败 → 记下错误，进入下一轮
仍失败 → 抛 StructuredOutputError
```

对应代码骨架：

```python
for attempt in range(retries + 1):
    if attempt > 0:
        messages.append(ChatMessage(role="user", content=f"上次…错误：{last_error}"))
    result = await client.chat(messages)
    messages.append(ChatMessage(role="assistant", content=result.content or ""))
    try:
        return parse_as_model(content, model_type)
    except ... as exc:
        last_error = str(exc)
```

要点：

- **错误要写进下一轮 Prompt**，模型才知道改什么  
- `retries=2` 表示最多共试 3 次（1 次首次 + 2 次重试）

---

### D. 演示为何 `--mock` 一次就能过

`stage02_structured_demo.py` 在 mock 时用了**脚本模式**：

```python
MockLLMClient(script=[
    ChatResult(content='{"goal":"...","steps":[...]}', tool_calls=[]),
])
```

第一次 `chat` 就返回合法 JSON，校验直接通过。  
这是为了让你先看清「调用方怎么用」；真模型时才会更常触发重试。

运行：

```powershell
python examples/stage02_structured_demo.py --mock
```

应看到缩进打印的 `goal` / `steps`。

## 常见卡点问答

**Q：一定要 JSON 吗？**  
A：初学阶段是。等你熟了再用各家 Structured Outputs 增强。

**Q：重试会不会很贵？**  
A：会多花调用。所以 Prompt 先写清楚，降低重试率；并限制最大重试次数。
