# 第4章第2节：长期记忆（跨会话）

## 写在前面

长期记忆跨过「关闭聊天再打开」。  
例如：用户喜欢简洁中文、项目用 Python、时区是上海。

---

## 本节你将学会

1. 长期记忆存什么、不存什么
2. 为什么「随便全记住」很危险
3. 如何运行 SQLite 小示例

---

## 生活例子

好朋友记得你对花生过敏——这是长期记忆。  
他不会把你三年里每句闲聊都背下来——那是噪音。

---

## 一步一步讲

### 第1步：更适合长期保存的内容

- 偏好（语言、风格）
- 稳定事实（公司名、技术栈）
- 明确要求「请记住」的内容

### 第2步：写入策略

| 策略 | 说明 |
|------|------|
| 显式写入 | 用户说记住才写（最稳） |
| 自动抽取 | 每轮抽事实（方便但易脏） |
| 人工审核 | 高价值记忆再入库 |

### 第3步：隔离

必须按 `user_id`（或租户）隔离，避免 A 的记忆泄漏给 B。

## 打开代码一起看（逐行教材版）

打开 `src/agent_lab/memory/long_term.py`。

### 1）一条记忆长什么样

```python
@dataclass
class MemoryItem:
    user_id: str  # 隔离维度：不同用户互不可见
    key: str      # 如 prefer_style
    value: str    # 如「简洁中文」
```

主键是 `(user_id, key)`：同一用户同一 key 只能有一个当前值。

### 2）建表

```sql
CREATE TABLE IF NOT EXISTS memories (
    user_id TEXT NOT NULL,
    key TEXT NOT NULL,
    value TEXT NOT NULL,
    PRIMARY KEY (user_id, key)
)
```

文件默认在 `data/long_term.db`（演示用 `data/long_term_demo.db`）。

### 3）`upsert`：有则改、无则增

```sql
INSERT ... ON CONFLICT(user_id, key) DO UPDATE SET value=excluded.value
```

适合「偏好被更新」：用户改口说喜欢详细回复，直接覆盖旧值。

### 4）`get` / `list`

- `get(user_id, key)` → 单个值或 `None`  
- `list(user_id)` → 该用户全部记忆（注入 Prompt 前可先过滤）

### 5）和短期记忆的分工

| | 短期 `ConversationMemory` | 长期 `LongTermMemory` |
|--|---------------------------|------------------------|
| 生命周期 | 一次会话 | 跨会话 |
| 存什么 | 对话原文/摘要 | 稳定事实与偏好 |
| 介质 | 内存 | SQLite 文件 |

运行演示后半段：

```powershell
python examples/stage04_memory_demo.py
```
