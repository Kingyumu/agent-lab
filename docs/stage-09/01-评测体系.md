# 第9章第1节：最小可行评测

## 写在前面

改 Prompt / 换模型 / 加工具时，若没有固定题集，你只能凭感觉说「好像更好了」。  
评测把感觉变成可对比的数字。

## 生活例子

背单词要有单词表和测验。  
改 Agent 也要有固定题集，否则无法对比版本。

## 本节你将学会

1. JSONL 题集长什么样  
2. `grade` 如何判分  
3. 为什么 demo 输出只是教学脚手架，真实评测要跑 Agent  

---

## 一步一步讲

1. 准备 JSONL 题：`input` + `expect_contains` + 可选 `expect_tool`  
2. 跑 Agent（或先用 demo 输出）  
3. 自动判分，统计通过率  
4. 每次改动都重跑  

---

## 打开代码一起看（逐行教材版）

打开 `evals/datasets/smoke.jsonl` 与 `evals/run_eval.py`。

### 1）题集：一行一题

```json
{"id": "calc_1", "input": "请计算 (3+5)*2", "expect_contains": ["16"], "expect_tool": "calculator"}
{"id": "rag_1", "input": "什么是 Tool Loop？", "expect_contains": ["工具", "循环"], "expect_tool": null}
{"id": "refuse_1", "input": "知识库里有火星门牌号吗？", "expect_contains": ["资料不足", "没有"], "expect_tool": null}
```

| 字段 | 人话 |
|------|------|
| `id` | 题号，方便对答案 |
| `input` | 扔给 Agent 的用户话 |
| `expect_contains` | 最终回答里必须出现的子串（全部满足才过） |
| `expect_tool` | 可选；要求过程中用过某工具 |

### 2）`load_cases`：按行读 JSON

```python
for line in path.read_text(...).splitlines():
    if line.strip():
        cases.append(json.loads(line))
```

空行跳过；一行坏 JSON 会整题崩——生产里可加 try/except。

### 3）`grade`：两条硬规则

```python
# 规则 A：答案必须包含期望子串
for token in case.get("expect_contains") or []:
    if token not in output:
        ok = False
        reasons.append(f"缺少: {token}")

# 规则 B：若指定了工具，必须真的调用过
if expect_tool and expect_tool not in (tools_used or []):
    ok = False
    reasons.append(f"未调用工具: {expect_tool}")
```

这叫「启发式自动判分」：便宜、可重复，但抓不住语义等价（说「十六」可能不及格）。进阶可用 LLM-as-judge，但仍建议保留确定性规则做烟雾测。

### 4）`demo_outputs`：离线替身

```python
return {
    "calc_1": ("结果是 16。", ["calculator"]),
    ...
}
```

教学版**没有**真的跑 AgentLoop，只是把「假答案」塞进判分器，让你先学会评测管线形状。  
真正有用时：`run(case["input"])` → 取 `reply` 与用过的工具名 → 再 `grade`。

### 5）汇总

```python
passed = sum(1 for r in rows if r["ok"])
print({"passed": passed, "total": len(rows), "rows": rows})
```

```powershell
python -m evals.run_eval
# 或
python examples/stage09_eval_demo.py
```

期望看到 `passed` 等于题数（当前 3/3）。
