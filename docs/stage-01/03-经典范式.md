## 先用一个生活例子：修电脑

用户：电脑上不了网。

**ReAct 风格的管家：**

```text
思考：先看看是不是网线/Wi-Fi问题
行动：检查 Wi-Fi 是否开启
观察：Wi-Fi 开着但没网
思考：那就 ping 一下网关
行动：ping
观察：不通
……
最终：给出结论
```

这就是「边想边做边看结果」。

## 一步一步讲清楚

### 第1步：ReAct = Reason + Act

经典写法会让模型输出 Thought / Action，程序执行后得到 Observation，再继续。  
优点：好懂。缺点：全靠自然语言写 Action，格式容易不稳。

### 第2步：Function Calling（本教材主路线）

现代 API 让模型返回结构化的 `tool_calls`（工具名 + JSON 参数）。  

> ReAct 的灵魂（循环）还在，但「行动怎么写」改成了官方结构化格式。

### 第3步：Plan-and-Execute

先列出步骤 1..n，再逐步执行；失败可重规划。适合长任务。第6章再练。

### 第4步：Reflexion / 校验

产出 → 检查（规则或另一模型）→ 不合格就重来。生产更常用规则校验。

### 第5步：它们如何连在一起

```text
用户目标
   ↓
需要外部行动？──否──→ 普通对话即可
   ↓是
步骤是否固定？──是──→ Workflow（代码写死流程）
   ↓否
进入 Tool Agent 循环（第3章重点）
   ↓
任务很长？──是──→ 加 Planner（第6章）
   ↓
需要多人设？──是──→ 多 Agent（第7章）
```

### 精读 Prompt（现在就做）

打开 `prompts/react_agent.txt`，逐条对照：

| 行意 | 对应范式元素 |
|------|----------------|
| 需要计算必须调 calculator | 强制 Action，禁止瞎编 |
| 工具失败时说明并给下一步 | Observation 失败后的 Reason |
| 得到足够信息后给最终答案 | 终止条件 |
| 忽略越权指令 | 安全边界（第2章加深） |
