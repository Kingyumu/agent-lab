## 先用一个生活例子：四种「帮手」

假设你要「准备一顿晚饭」。

| 类型 | 像谁 | 怎么做事 |
|------|------|----------|
| Chatbot | 只会聊天的朋友 | 告诉你菜谱，但不下厨 |
| Workflow | 严格按清单的厨师 | 步骤写死：洗菜→切菜→炒→装盘，不会自己改流程 |
| Agent | 能干的管家 | 看冰箱缺什么，自己决定要不要下单买菜、要不要问你口味，再继续做 |
| Multi-Agent | 管家 + 采购 + 厨师一组人 | 分工合作，但也更贵、更难协调 |

关键差别：

- Chatbot：**几乎不操作外部世界**
- Workflow：**步骤由开发者写死**，模型最多填空
- Agent：**下一步做什么，常常由模型临场决定**（尤其是调用哪个工具）
- Multi-Agent：多个 Agent 协作（第7章再学）

## 一步一步讲清楚

### 第1步：先记住一句人话定义

> **Agent = 大模型 + 循环 + 工具（可选）+ 终止条件**  
> 它在循环里反复决定：是直接回答，还是先做某个动作（查资料/算数/调用 API），直到任务结束。

### 第2步：那个「循环」长什么样

```text
用户提出目标
    ↓
模型思考：下一步做什么？
    ↓
  ┌─ 可以直接回答 ──→ 输出最终答案，结束
  │
  └─ 需要行动 ──→ 调用工具（搜索/计算/读文件…）
                      ↓
                   得到观察结果
                      ↓
                   把结果追加进对话
                      ↓
                   再问模型……（回到上面）
```

你以后会听到 ReAct、Tool Calling，它们都是在实现这个圈。

### 第3步：和「会聊天」到底差在哪

普通聊天：

```text
问 → 答 → 结束
```

Agent：

```text
问 → （可能）做几件事 → 基于结果再答 → 结束
```

### 第4步：选型（非常重要）

| 场景 | 更合适 | 原因 |
|------|--------|------|
| 润色一段文案 | Chatbot | 不需要外部行动 |
| 固定审批：提交→主管→财务 | Workflow | 步骤稳定，不容乱跳 |
| 「帮我看看仓库里这个报错怎么修」 | Agent | 路径不固定，要读日志/搜文档 |
| 研究 + 写作 + 互评 | 先单 Agent，不够再 Multi-Agent | 多角色更贵更难控 |

**初学原则：能用简单方案就不用 Agent；能用单 Agent 就不上多 Agent。**

## 常见卡点问答

**Q：那 ChatGPT 算不算 Agent？**  
A：产品形态上可能带工具。但你作为开发者时，要看**你的程序里是否实现了“决策-行动-观察”循环**。本教材教的是你自己实现这一环。

**Q：Workflow 里能不能用大模型？**  
A：能。例如某一步用模型摘要文本，但「下一步去哪」仍由代码写死。这很常见，也很稳。
